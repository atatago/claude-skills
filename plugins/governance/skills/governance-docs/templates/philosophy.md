# 哲学(標準)

迷ったときの判断の拠り所。決まりがない場面で使い、経験に応じて更新する。憲法・法律と矛盾する場合は、憲法・法律が優先される。
プロジェクトに合わない項目は書き換えるか外してよい。外した・変えた理由は改正履歴に書く。

1. **迷ったら利用者の側に立つ。** 画面の文言・順序・負担は、初めて使う人の目で見直す。
2. **小さく作って確かめる。** 迷ったら小さな試作で触ってみてから広げる。進み具合が見える形で区切る。
3. **利用者の失敗を責めない。** エラーや間違いは、次にどうすればよいかを示す機会にする。
4. **分からないことを分かったように書かない。** 推測は推測と、諸説あるものは諸説あると示す。見栄えのために正確さを犠牲にしない。
5. **守ることも品質のうち。** ライセンス・セキュリティ・プライバシーの遵守は、完成度の一部と考える。
6. **戻せる形で変える。** 変更は小さく分け、壊れたら戻せるようにする。戻せない操作は、先に確かめる。
7. **繰り返す失敗は仕組みで止める。** 失敗はまず記録し、同じ種類が繰り返されたら、注意書きを足すより先に、チェックや自動化で止められないかを考える。止める仕組みは少なく、太く。
8. **ルールには理由を残す。** 足した理由ときっかけがあれば、効いているかを確かめられ、要らなくなったら外せる。
